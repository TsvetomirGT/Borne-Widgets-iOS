# Borne Widgets

iOS app: a library of hand-crafted home-screen widgets (weather, clock, sun & moon, calendar). Personal project + portfolio, likely open source — code is read by strangers, keep it clean and commented where non-obvious. Visual craft is the point.

Specs: `docs/superpowers/specs/` (v1 design, calendar design). Read the relevant one before changing behaviour.

## Toolchain

Xcode 27.x, iOS SDK 27, deployment target **iOS 26.0**, Swift 6 language mode, SwiftUI, WidgetKit, EventKit, Swift Testing. Project generated by **XcodeGen** from `project.yml` — `.xcodeproj` is git-ignored; never edit it, edit `project.yml` and rerun `xcodegen`.

## Layout

- `App/` — the app: library (filter chips, previews), design detail, settings. Chrome uses **native Liquid Glass only** (`glassEffect`, `.glass`/`.glassProminent`, `GlassEffectContainer`, `Tab(role: .search)`). Never fake glass with materials/blurs. Glass on controls, never on widget previews.
- `WidgetExtension/` — one `Widget` per design + `TimelineProvider`s. Thin: views come from BorneDesigns.
- `BorneKit/` — local Swift package:
  - `BorneCore` — Foundation-only (plus EventKit reader behind a protocol): models, Open-Meteo client, `WeatherStore`, `SettingsStore` (App Group), astronomy, calendar math, `DesignCatalog`. Tested on macOS.
  - `BorneDesigns` — SwiftUI widget views, `DesignRegistry`, entries. Styles live in `Styles/<Style>/`; only `Editorial` exists.
- `Config/Base.xcconfig` — `BUNDLE_PREFIX`, `APP_GROUP_ID`; includes optional git-ignored `Config/Local.xcconfig` (team + prefix for device builds, see `.example`).

## Commands

```sh
swift test --package-path BorneKit                      # all unit + design tests (macOS, fast)
RENDER_DIR=/tmp/r swift test --package-path BorneKit --filter renderAllCards   # PNG of every card, light/dark, all states
./build.sh <simulator-udid>                              # xcodegen + xcodebuild into .build/dd, log .build/xb.log
xcrun simctl install <udid> "$PWD/.build/dd/Build/Products/Debug-iphonesimulator/Borne.app"
xcrun simctl launch --terminate-running-process <udid> <bundle-id>
xcrun simctl list devices available                      # find udids
```

Device: `xcodebuild -project BorneWidgets.xcodeproj -scheme BorneWidgets -destination 'id=<device-udid>' -derivedDataPath .build/dd-device -allowProvisioningUpdates build`, then `xcrun devicectl device install app --device <udid> .build/dd-device/Build/Products/Debug-iphoneos/Borne.app`. Free Personal Team: app expires after 7 days, user must trust the developer in Settings → General → VPN & Device Management.

Always build both an iOS 27 and an iOS 26 simulator after touching widget families or `#available` code.

## Gotchas (learned the hard way)

- **Bundle id follows `BUNDLE_PREFIX`.** When `Config/Local.xcconfig` exists it changes the id for simulator builds too. Launch with the id actually built (`xcrun simctl listapps <udid> | grep borne`), or you will run a stale copy and think your change didn't work.
- **Xcode 27 has no Simulator.app** — use `/Applications/Xcode.app/Contents/Applications/DeviceHub.app`.
- **Widget gallery empty** on a simulator usually means `chronod` crashed; reboot the simulator (`xcrun simctl shutdown/boot`).
- Widgets on the home screen keep old layouts until their timeline reloads — remove and re-add to check a change.
- **Full-page widget** = iOS 27 `systemExtraLargePortrait`. Always go through `WidgetSize.family` / `WidgetSize(family)` which gate it with `#available(iOS 27.0, macOS 27.0, *)`.
- **Real widget sizes are smaller than preview sizes.** iPhone 18 Pro: small 164.33², medium 349.67×164.33, large 349.67×365, full page 349.67×565.67. `LayoutFitTests` checks every card against these — keep it green; content that overflows pushes the gold keyline off.
- View types are `@MainActor`; pure static helpers called from tests must be `nonisolated`.
- `safeAreaBar` on the library dimmed the large title — filter bar uses `safeAreaInset`.
- Widget extension reads EventKit directly using the app's Calendar permission; event data is never copied to the App Group or sent anywhere.

## Design rules (Editorial)

- Every colour comes from `EditorialPalette(mode, scheme)`: slate in dark, ink-on-paper in light, monochrome in tinted/clear (`widgetRenderingMode`). Never hard-code `EditorialTheme` colours in views. Mark key elements `widgetAccentable()`.
- Fonts: `EditorialTheme.numeral` (serif), `.italic`, `.label` (mono small caps via `EditorialCaption`). No bundled fonts.
- Widgets get their background via `containerBackground` (`DesignRegistry.background`), `drawsBackground: false`; app previews draw it themselves.
- App previews render through the **same** `DesignRegistry.view` as widgets — never special-case previews.
- Every design must look complete in its empty/denied states (no location, no calendar access, stale data).
- Labels must not be ambiguous: the user has pushed back on unlabeled markers and on "low/high" that meant window extremes rather than today's. Prefer explicit values over clever markers.
- Temperature curve: now + `EditorialTheme.curveHours` (6) hours, a value per hour, orange Now dot.

## Adding a design

1. `DesignCatalog`: new `DesignInfo` (id = WidgetKit kind), add to `all`; new `WidgetCategory` case if needed.
2. Views in `BorneDesigns/Styles/<Style>/<Category>/`, cases in `DesignRegistry.content`.
3. Entry type in `Entries.swift` if new data; thread it through `DesignRegistry.view`, `DesignWidgetView`, `PreviewCard`, tests.
4. `Widget` + provider in `WidgetExtension/`, register in `BorneWidgetBundle`.
5. Update catalog count tests, check renders (light/dark, empty states) and fit tests, README designs table.

## Workflow

- TDD: failing test first (Swift Testing), then code. Pure logic goes in BorneCore so it's testable on macOS.
- After visual changes: render PNGs and look at them, then run on the simulator and screenshot (`xcrun simctl io <udid> screenshot`).
- Branch `feat/v1`; commits are Conventional Commits (`feat(designs): …`, `fix(core): …`). No remote yet — don't push or merge without asking.
- Never commit personal data (team id, device ids, email): those belong in `Config/Local.xcconfig`.
- Weather: Open-Meteo, no key; keep the "Weather data by Open-Meteo.com" attribution (CC BY 4.0).
